## Input boundary for the next integration

`src/input/switch-machine.mts` is an application event contract, not a claim that the current Pico speaks a wire protocol. Create a fresh unpredictable instance ID on every page load. Never persist or restore input captures, epochs, sequence state or selection effects. Consume each returned selection once; the reducer never stores a replayable effect. A selection is not speech authorization.

The eventual serial adapter must request a fresh current-state response using the current epoch. It must not relabel old queued data, derive release from a timer, or treat console READY/UP text as a synchronization response. It must validate bounded framing, protocol version, epoch, sequence, matching press and message freshness before forwarding events. Lost focus/visibility, port loss, read/write/queue errors and relevant UI changes retire the epoch and cancel pending input. Reconnect while pressed must wait for an observed release and then a new deliberate cycle. Full UI recovery must provide the separately specified Resume route. AI/gaze must not call the input lifecycle or replace a held target.

Timer callbacks carry an epoch and are inert when retired, held, disconnected or inactive. Timer cadence is outside the pure reducer. Runtime serial framing, freshness deadlines, heartbeat/liveness handling, real transport tests and final UI recovery remain unimplemented at this approval checkpoint.
